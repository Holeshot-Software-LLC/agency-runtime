# AR-404 next twenty unfinished records: source-led triage

## Outcome and scope

Of these twenty records, eleven primarily hold implementation/live evidence,
six contain obsolete or contradictory requirements, and three describe remaining
code scope. Those three are **two concrete implementation candidates plus their
parity umbrella**, not three newly discovered bugs. No record is closed or given
an acceptance verdict by this inventory.

This is one bounded source review, not twenty independent reviews. The frozen
source is main merge `cbba0fd9`, with its faithful ledger checkpoint `887c8712`.
Subsequent installed-delivery work is outside that identity. Inspection used
canonical issue documents, the cited source, and existing decisions; no models,
native host commands, owner configuration writes, CI, or tests ran for this
triage. Historical checked boxes and reported tests are not fresh proof.

The order is canonical `created` date, then numeric AR identifier, beginning at
AR-195; `done` and `wont_do` records are excluded. AR-258's historical Windows
machine repair and AR-263's Windows Desktop reproduction are excluded. AR-197
is included only for its cross-platform owner-authority assertions; AR-262 is
included for its shared dashboard coordinator. Neither inclusion authorizes or
claims Windows testing.

Classes below are provisional work-routing labels: **proof held** means current
implementation exists but does not establish every literal/live criterion;
**reconcile** means later policy or source contradicts part of the checklist;
**code scope** means specific remaining implementation is visible in source.

## Recommended execution order

1. **AR-270: repair the closed OpenClaw two-path binding.** This is the strongest
   current correctness gap. Inspect the retained native shape first; keep exact
   identity, managed install receipt, canonical local paths, installed-root
   containment, ambiguity rejection, locked re-planning, and rollback retention.
2. **AR-251: extend plain cards one command family at a time.** Reuse the existing
   renderer and snapshots; no new runtime dependency or policy change is needed
   for the already-requested presentation scope.
3. **AR-236/250: refresh the parity matrix and settle upgrade UI scope.** The
   missing UI is observable, but its own acceptance explicitly defers it.
   Do not implement a broad mutation surface merely to clear an umbrella.

In parallel, reconcile AR-197/199/201/209/235 against current policy, preserving
literal historical criteria rather than silently checking or rewriting them.
AR-250's self-deferral needs an explicit disposition. The eleven proof-held
records should reuse source-equivalent evidence where justified and retain
exact missing live obligations; they are not eleven invitations to rewrite
working runtime code. Broader staffing performance and cross-host success remain
important, but this inventory does not identify a further concrete optimization
or justify a claim of quality equivalence.
