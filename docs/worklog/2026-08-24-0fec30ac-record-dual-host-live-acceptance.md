# Worklog detail: Record dual-host live acceptance

## Purpose

Record the completed, host-scoped parent-runtime acceptance evidence for both
OpenClaw and Hermes without overstating delegation, native-child delivery,
Rule 4, matrix movement, or actual upstream model identity.

## Approach

The evidence package correlates each fresh native status, harmless skill, and
substantive turn with Store runs, routing decisions, specialist and skill rows,
provider receipts, terminal finalization, exact five-line headers, and Telegram
delivery. Native host routes remain on `task-general`; only the two Agency
harness profiles request the opaque `task-agency-router` LiteLLM alias.

The package preserves all earlier failed attempts, redacts transport-derived
session prefixes, records immutable configuration and launcher hashes, and
adds AR-280 for the newly observed Hermes internal post-response lifecycle
calls. No hosted tracker, pull request, Action, or publication operation was
performed.

## Challenges encountered

Hermes produced separate non-user post-response preflights after successful
reply delivery. They consumed strict-planner attempts on the correct Agency
profile and failed without blocking the accepted user turns. AR-280 retains the
problem and requires a positively authenticated lifecycle discriminator before
any repair.

Final validation also retained three environment-only failures: a policy check
without checkout-bound `PYTHONPATH`, unavailable bare-shell Ruff, and focused
pytest attempts using an unsafe temporary configuration parent or untrusted
group-writable fixture launcher. Changed-input runs used the checkout tools, an
owner-private temporary root, and a root-owned CI fixture interpreter and then
passed.

## Decisions and alternatives

The LiteLLM router alias remains model-agnostic and is never promoted to an
actual answering-model claim. No proxy callback was added to the shared
service, so actual upstream model identity remains unavailable. The Hermes
post-response defect is recorded rather than weakened around fail-closed user
turn boundaries.

## Verification

- OpenClaw and Hermes each delivered fresh status, skill, and substantive
  Telegram responses with Store-backed five-line headers.
- Every accepted Agency workforce receipt used the host-selected
  `linux-task-agency-router` profile, provider type `litellm`, and exact
  `task-agency-router` alias/model-group with zero cross-provider fallback.
- Final Store source and online backup integrity are `ok`, schema is 47, and
  contractors remain 15.
- Focused OpenClaw/Hermes installer, dispatch, inference-profile, header, and
  Store tests passed 304 with one intentional skip.
- Ruff lint and format checks plus documentation metadata, policy availability,
  worklog, verification, and diff checks passed.

  owns the Hermes internal post-response preflight exclusion.
- Native-child delivery, delegation, Rule 4, and AR-119 matrix-cell proof remain
  outside this parent-runtime acceptance package.
