# Worklog detail: Unseal disposable Hermes guard

## Purpose

Restore the Ubuntu installed-distribution smoke gate without weakening the
AR-328 production contract that keeps Hermes' generated bytecode namespace
sealed against unmanifested `.pyc` files.

## Approach

The smoke harness now owns a small context wrapper around its existing private
temporary home. Its `finally` path identifies only the exact generated Hermes
plugin and delegates to the same guarded mode transition used by the atomic
installer. If neither guard path exists, cleanup is unchanged. If a partial,
linked, or non-regular guard exists, the existing strict metadata checks fail
closed rather than widening deletion authority.

The production bundle remains 0500/0400 throughout installation, import, and
runtime validation. Only smoke's isolated generated copy becomes 0700/0600
immediately before the already-authorized private-tree cleanup.

## Challenges encountered

PR #337's first Ubuntu distribution job completed artifact construction,
metadata checks, wheel installation, the installed-distribution report, and CLI
surface checks before failing at temporary cleanup. Windows passed because its
private-tree remover already has a platform-specific read-only retry. The same
full smoke-isolation test reproduced the POSIX `PermissionError` locally.

The first local decision-conformance invocation used the ambient umask and was
rejected by the expected private-namespace boundary before its baseline. The
required 0077 rerun passed; the negative did not indicate a source mutation.

## Decisions and alternatives

Generic private-tree deletion was not broadened to rewrite arbitrary POSIX
descendant permissions. Uninstall was also unsuitable because its retention
tree intentionally preserves the sealed bundle. The bounded smoke-only mode
transition reuses ADR-0191's exact guard validation and leaves foreign host
policy, real installations, credentials, and model routes untouched.
