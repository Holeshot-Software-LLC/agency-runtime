# Worklog detail: Merge PR #114 production hardening

## Purpose

Merge the reviewed WSL service-trust and authoritative Agency canary-control
changes after every hosted gate passed.

## Approach

PR #114 retained normal-Linux hardening while adapting the WSL systemd namespace
boundary, then bound generated host hooks and isolated canaries to authoritative
global control. The merge also carries the final portability and coverage
repairs needed for an exact cross-platform candidate.

## Challenges encountered

The final boundary required distinguishing a secure normal-Linux `PrivateTmp`
policy from WSL namespace remapping, and distinguishing Agency-on evidence from
native-only proof without allowing stale headers or attestations to pass.

## Decisions and alternatives

The implementation omitted only `PrivateTmp` after positive WSL identification
and retained all other service restrictions. Native-only canaries require the
opposite evidence contract and never persist an Agency attestation.

## Verification

PR #114 passed exact line and branch coverage, Ubuntu Python 3.10-3.14, Windows
Python 3.10 and 3.14, portability contracts, routing/delegation performance,
dashboard UI, deterministic source audit, artifact byte parity and smoke,
dependency review, and CodeQL.

## Follow-ups

None. Package publication and release tagging remain separately authorized
release actions.
